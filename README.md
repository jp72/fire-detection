# fire-detection

Небольшая C++/OpenCV-утилита для выделения пикселей, похожих по цвету на пламя.
Продолжение университетского эксперимента: без нейросетей, обучения и GUI.

**Это экспериментальная цветовая сегментация, не пожарная сигнализация.**
Оранжевые предметы и освещение могут вызывать ложные срабатывания;
необычный цвет пламени может приводить к пропускам.

## Сборка

Нужны C++11-компилятор, CMake >= 3.16 и OpenCV 4 (core, imgproc, imgcodecs).
Например, в Debian/Ubuntu:

```sh
sudo apt install build-essential cmake libopencv-dev
cmake -S . -B build-cli
cmake --build build-cli
ctest --test-dir build-cli --output-on-failure
```

Используется отдельный каталог `build-cli`, чтобы не затрагивать старый `build`.

## Использование

```sh
./build-cli/fire photo.jpg
./build-cli/fire photo.jpg --method rgb --output rgb-result
./build-cli/fire photo.jpg --method ycrcb --output ycrcb-result
./build-cli/fire photo.jpg --min-area 60 --output filtered
./build-cli/fire --help
```

По умолчанию: метод `ycrcb`, префикс `fire-result`.
Программа сохраняет:

- `<prefix>-mask.png`: бинарная маска, белый означает пиксель-кандидат;
- `<prefix>-overlay.png`: исходное изображение с зелёными прямоугольными рамками
  вокруг связных областей кандидатов. Каждая отдельная область получает свою рамку;
  если кандидатов нет, изображение остаётся без рамок.

Перед построением рамок применяется морфологическое замыкание 3×3: оно соединяет
близкие фрагменты и закрывает мелкие разрывы. Затем удаляются связные области
площадью меньше `--min-area` (по умолчанию 25 пикселей, минимум 1).
Площадь считается по пикселям маски после замыкания, не по площади рамки.
Порог зависит от разрешения: его увеличение убирает шум, но может скрыть мелкое
или далёкое пламя. Цветовые ложные срабатывания на коже и тёплых предметах
этот этап сам по себе не устраняет.

Сохранённая маска и число пикселей относятся к результату после этой обработки.
В stdout выводится количество и доля пикселей-кандидатов — это **не вероятность пожара**.
Окно не открывается. Для путей с пробелами используйте кавычки.
Если префикс включает каталог, этот каталог должен уже существовать.
Файлы результата с тем же именем перезаписываются; не используйте путь исходника
в качестве имени выходного файла. Ошибки аргументов, чтения или записи дают код возврата 1.

## Методы

- **RGB**: `R >= 115`, `R >= G >= B`, насыщенность HSV между двумя
  зависящими от B границами из исходного эксперимента. Старый комментарий
  о пороге 115–135 интерпретирован как диапазон выбора порога, а не диапазон
  допустимых значений R. Исправлено направление верхнего ограничения насыщенности.
- **YCrCb**: `Y > Cb`, `Cr > Cb`, `Y > mean(Y)`, `Cb < mean(Cb)`,
  `Cr > mean(Cr)`, `abs(Cb - Cr) >= 40`. Средние вычисляются по всему изображению,
  поэтому результат зависит от фона; однородная заливка не проходит строгие сравнения.

Маски обнуляются и объединяют все условия выбранного метода. Старые полиномы
без описанного источника и незавершённый HSI-код исключены из реализации.
Методы не откалиброваны на датасете и не анализируют движение или форму пламени.

## Тесты

CTest проверяет нейтральные изображения, синтетический цветовой кандидат,
нулевой фон, размеры масок на прямоугольных изображениях, удаление шума,
соединение фрагментов, сохранение областей на границе и базовые случаи CLI.
Это проверки реализации, не оценка качества обнаружения огня.

Следующий этап — проверка на размеченных изображениях с огнём и без него,
затем при необходимости поддержка видео и временное подтверждение.
